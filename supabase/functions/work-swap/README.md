# 근무 교환

두 날짜의 정근을 교환합니다. 상대방 수락 뒤 관리자가 최종 승인해야 게시된 근무표와 동일한 초안에 반영됩니다. 당직·8진·데스크·조근·타 부서 지원 표기·VW2·휴가·퇴근·비번은 제외합니다. 대신 근무할 날은 휴무여야 합니다. 서로 다른 부서인 경우 각 직원의 해당 날짜 소속 부서에 정근을 배정합니다.

신청/대화는 `nd_swaps`, 관리자 알림 수신자는 `nd_swap_admins`에 별도로 저장합니다. 관리자 메뉴의 교환 신청 목록에서 관리자 비밀번호를 확인하면 해당 계정이 알림 수신자로 등록됩니다. 기기에 기존 푸시 구독이 있어야 앱 밖 알림이 도착합니다. 앱 내부 알림/채팅은 15초마다 확인합니다.

`schema.sql` 적용 후 `supabase/functions/work-swap`을 배포합니다. 서버에는 기존 SUPABASE_SERVICE_ROLE_KEY와 VAPID_PRIVATE/PUBLIC/SUBJECT 환경변수를 사용합니다. 비밀키를 프론트엔드에 넣지 않습니다.

현재 앱의 이름/기기 로그인(`login_log`)을 그대로 연동합니다. Supabase Auth 로그인으로 교체한 구조는 아닙니다. 관리 동작에는 서버에서 비밀번호를 다시 확인합니다. 기존 공개 데이터/로그인 방식의 신뢰 모델을 넘어서는 본인 인증을 제공하지 않습니다.

승인은 신청 revision과 근무표 updated_at을 확인한 DB 트랜잭션으로 처리합니다. 신청 뒤 근무/직원 정보가 바뀌면 재신청해야 합니다. `_swapRevision`은 오래된 브라우저 저장이 승인 내용을 덮어쓰는 것을 막습니다. 이전 버전 백업 복원도 이 검사로 차단되므로 승인 이력과 대조 후 별도 처리해야 합니다.

검증: `node swap-backend/test.mjs` (격리된 근무표·서버 모의 테스트), `test-db.sql` (트랜잭션 내 임시 신청, 마지막에 롤백), `verify-live.cjs` (비로그인 접근 거절 검사). 테스트는 실제 직원의 교환 신청/채팅/푸시를 생성하지 않습니다.
